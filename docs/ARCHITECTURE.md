# Architecture

## Product boundary

Tabular ML is a separately owned Python distribution, not copied application
code inside `ml_server`. It exports one Flask blueprint and one standalone
application factory. This mirrors the companion-service ownership pattern used
by PDF Tools while keeping the package testable and releasable on its own.

## Runtime topology

~~~text
Browser
  |
  +-- /tabular_ml/ ---------------- bundled React application
  |
  +-- /tabular_ml/api/v1/* -------- versioned JSON/file API
          |
          +-- API adapters -------- validation, HTTP status, safe errors
          +-- application services  workflow/session orchestration
          +-- pure core ------------ profiling, transforms, models, metrics
          +-- bounded memory store - datasets, fitted runs, expiry
          +-- dataset package ------ tracked CSV + JSON metadata
~~~

Standalone mode registers the blueprint on a small Flask app. Integrated mode
registers that same exported blueprint on `ml_server`; routes and frontend
assets are therefore identical in both modes.

## Backend module contract

- `api/`: Flask-only adapters. It may parse requests but contains no ML logic.
- `core/schema.py`: semantic type inference, target/task recommendation, data
  health and leakage checks.
- `core/preprocessing.py`: immutable configuration and sklearn transformers.
- `core/outliers.py`: detection and treatment with explainable row/feature
  summaries.
- `core/algorithms.py`: capability-rich estimator registry and validated
  parameter schemas.
- `core/training.py`: split, stratification, cross-validation, fitting,
  evaluation, comparison, feature importance, and prediction.
- `core/visualization.py`: chart-ready, bounded payload computation.
- `services.py`: workflow orchestration and in-memory lifecycle.
- `store.py`: lock-safe, TTL- and capacity-bounded artifact storage.

Core modules do not import Flask. Tests exercise them without a web server.

## Frontend

React + TypeScript + Vite provides a guided workspace:

1. Choose demo data or upload a file.
2. Inspect inferred schema and data quality.
3. Configure preparation and outlier policy.
4. Select a target and compare compatible algorithms.
5. Inspect metrics, diagnostics, and feature behavior.
6. Enter/upload inference rows and export results.

Plotly is bundled locally. Each chart owns a visible gear action for titles,
fonts, palette, dimensions, axes, legend, annotations, and export settings.
No CDN, analytics, remote fonts, or runtime network dependencies are allowed.

## State, privacy, and limits

Uploaded bytes are parsed in memory. Dataset frames and fitted pipelines live
in a process-local store with a short idle TTL, maximum session count, row
limit, column limit, and upload-size limit. Eviction destroys references.
Generated downloads are streamed from memory. Filenames, cell values, model
predictions, and uploaded bytes are never logged.

Joblib/pickle model uploads are intentionally not accepted because deserializing
untrusted Python objects is unsafe. Users can download an artifact generated by
their current trusted process and perform inference through the active run.

## Upstream audit and planned improvements

The referenced `ml_server_all_in_one/plugins/tabular_ml` implementation was
audited from its public repository and a matching local reference checkout.
It provides:

- Titanic and Adult Income only.
- Basic CSV loading and a process-local session.
- Mean/median/most-frequent imputation, one-hot encoding, two scalers.
- IQR, z-score, and Isolation Forest outliers.
- Histogram, box, and Pearson correlation payloads.
- Logistic/Ridge, Random Forest, Gradient Boosting, Extra Trees, SVM
  classification, sklearn MLP, and optional Torch MLP.
- A single train call with three-fold cross-validation and a small metric set.

This repository separates pure core logic, expands metadata and workflow
validation, adds Excel, richer semantic typing/preparation, broad estimator and
metric catalogs, comparison and inference, robust multiclass/regression
diagnostics, configurable charts, clearer help, safer limits, and substantially
broader tests.

## Compatibility contract with ml_server

Public import:

~~~python
from tabular_ml_service.app import create_app, tabular_ml_bp
~~~

The host installs this repository in editable or wheel form and registers
`tabular_ml_bp`. The blueprint owns `/tabular_ml/*`. The host catalog links to
`/tabular_ml/`, and host tests verify index, health, datasets, and one compact
training flow.
