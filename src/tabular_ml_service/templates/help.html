SCIENTIFIC GUIDE · RELEASE 0.2.0

From table to evidence

Tabular ML profiles a CSV/XLSX table, separates evaluation evidence, fits preprocessing inside each training fold, compares CPU models, and evaluates the selected pipeline on untouched holdout data.

  1. Profile types, missingness, target, and leakage risks.
  2. Choose a random, stratified, grouped, or time-aware split.
  3. Fit imputation, encoding, scaling, and the model inside each fold.
  4. Compare cross-validation distributions, not one lucky score.
  5. Evaluate the held-out set once; explain and export the whole pipeline.

Main equations

\[ z_{j} \;=\; \frac{x_{j} - \mu_{\text{train},\,j}}{\sigma_{\text{train},\,j}} \]

Scaling statistics come from the training folds only. Validation data must never influence preprocessing.

\[ R^{2} \;=\; 1 \;-\; \frac{\displaystyle\sum_{i}\bigl(y_{i}-\hat{y}_{i}\bigr)^{2}}{\displaystyle\sum_{i}\bigl(y_{i}-\bar{y}\bigr)^{2}} \]

Explained variance relative to simply predicting the target mean.

\[ \begin{gathered} F_{1} \;=\; \frac{2\,P\,R}{P + R} \\[6pt] P = \frac{TP}{TP + FP}, \qquad R = \frac{TP}{TP + FN} \end{gathered} \]

Balances false-positive and false-negative performance in one classification number.

\[ \widehat{\mathrm{CV}} \;=\; \frac{1}{K}\sum_{k=1}^{K} m\bigl(f_{-k},\, D_{k}\bigr) \]

Each fold is scored by a model that never saw it. That is what makes the estimate honest.

where
\(x_{j}\)raw value of numeric feature \(j\)
\(y_{i},\,\hat{y}_{i}\)observed and predicted target for sample \(i\)
\(TP,\,FP,\,FN\)true positives, false positives, false negatives
\(f_{-k},\,D_{k}\)model fitted without fold \(k\), and that fold's held-out data

Critical inputs

Target and task
Define what is predicted and which metrics are scientifically meaningful.
Features
Must exist at prediction time; identifiers, future information, and target proxies create leakage.
Split policy
Must preserve groups, time order, or class balance where the data-generating process requires it.
Hyperparameters
Control capacity, regularization, interpretability, and CPU cost.

Reading results

  • Compare holdout performance with the full cross-validation distribution.
  • Inspect confusion matrices, residual patterns, subgroup behavior, and class balance.
  • Permutation importance shows predictive dependence, not causation.
  • Preserve the fitted preprocessing-and-model pipeline together.

Limits and failure modes

  • Small or shifted datasets can produce unstable estimates.
  • Random splits are misleading for grouped or time-ordered observations.
  • Association and feature importance do not establish a physical mechanism.
  • Deployment requires monitoring drift, errors, and domain constraints.

Privacy

This workbench runs on the office intranet and is CPU-only. Your table is held in a session store for the lifetime of your work and is never sent outside the office network. No personal information is collected.
